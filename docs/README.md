# Документация проекта

Этот проект (`weekly-report-bot`) уже описан для разработчиков в корневом
[`../README.md`](../README.md) (стек, установка, сборка, переменные окружения) и в
[`../CLAUDE.md`](../CLAUDE.md) (архитектура, для ИИ-ассистентов). Здесь - более прикладная
документация: как эксплуатировать бота день в день и что делать при типичных проблемах.

## Файлы в этой папке

- **[`operations-guide.md`](./operations-guide.md)** - основная инструкция: что делает бот,
  как устроен еженедельный отчёт, как менять расписание, что делать при сбоях и куда смотреть
  в логах. Начните отсюда.
- **[`data-reference-files.md`](./data-reference-files.md)** - подробно про два
  xlsx-справочника (`divisions.xlsx`, `daribar_crosswalk.xlsx`): структура столбцов, известные
  проблемы качества данных (порядок ФИО, статус "Закрыта", дубли кодов) и как их исправлять.
- **[`manual-report-testing.md`](./manual-report-testing.md)** - как сгенерировать недельный
  отчёт локально из реальных данных, не отправляя его в Telegram - удобно для проверки после
  правки справочников или дизайна.
- **[`weekly-report-changes-2026-07-23.md`](./weekly-report-changes-2026-07-23.md)** - журнал
  конкретных изменений от 2026-07-23 (редизайн отчёта под корпоративный шаблон + исправления
  данных). Первая запись в истории изменений; при следующих значимых правках имеет смысл
  добавлять рядом новый файл с датой в том же формате.
